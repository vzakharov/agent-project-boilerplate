## Body

## The problem

`$GH_TOKEN` is the operator's own identity, so an agent's reply and the operator's guidance land on GitHub under the same `@login`. The only thing separating them is the Claude Code attribution footer that every agent-authored post carries.

`/handle`'s review lane turns on exactly that distinction — its tail test asks whether a thread's newest comment is guidance nobody has answered — and today the discrimination is done by the agent reading `docs/pr/<n>/pr.md` and noticing the footer, with the rule stated as prose in `.claude/skills/handle/SKILL.md` § "Step 2":

> **Reading the tail needs a tell, because the login doesn't provide one.** … a tail comment with the footer is your own reply, one without it is the operator.

That is a mechanical string test being run as a judgment call, on every comment, in the middle of a long export. It fails in the direction that costs the most: miss the footer on your own reply and you re-work a thread that was already answered; read a footer onto the operator's comment and you skip guidance addressed to you. It also depends on the footer surviving into the rendered export at all, which nothing asserts.

## What to do

Move the test into `scripts/export-github-item.py`, which already parses every comment and owns how they render.

`scripts/gh_export/markdown.py:12`'s `login_of()` is the one place all three renderers (`markdown.comments_section`, `reviews.review_section`, `timeline.timeline_section`) get an author from, so the label can be added once there rather than per-renderer.

- Detect the footer on a comment body — the trailing `---` rule plus `_Generated by [Claude Code](https://claude.ai/code)_`, tolerant of trailing whitespace and of the `claude.com/claude-code` variant the harness sometimes appends.
- Label the comment in the export from that, not from the login: something a reader cannot misparse, e.g. `### Comment by @vzakharov (agent) on …` vs `### Comment by @vzakharov (operator) on …`.
- Strip the matched footer from the rendered body. It carries no information once the label exists, and it repeats on every agent comment in a file that runs to well over a thousand lines.
- Keep the raw login visible either way — the label is an annotation on it, not a replacement, and a third-party reviewer must still read as themselves.

Then cut the prose. `.claude/skills/handle/SKILL.md` § "Step 2" stops explaining how to tell the two apart and just names the field the export gives it. CLAUDE.md § "Writing things down" — a rule the script enforces is a rule the skill does not restate.

## Acceptance

- A comment carrying the footer exports as agent-labelled; the same comment with the footer removed exports as operator-labelled.
- Both footer variants (`claude.ai/code`, `claude.com/claude-code`) are recognized.
- A footer-shaped string in the *middle* of a body is not treated as the footer — only a trailing one is.
- `/handle`'s Step 2 no longer describes the string test, and cites the export's label instead.
- `bash scripts/vet.sh` passes.

## Note

This does not make the footer optional. It stays mandatory on every agent-authored post (per this repo's harness rules) precisely because it is now the machine-read signal rather than a courtesy — worth saying in whichever doc ends up owning the label.
