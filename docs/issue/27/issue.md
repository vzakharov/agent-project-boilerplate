## Body

## The gap

`CLAUDE.md`'s suppression principle governs **whether** a suppression is
allowed, but says nothing about **where** it goes once it is:

> **Never add lint-suppression comments without explicit user confirmation.**
> […] If the rule is genuinely wrong for that case, ask the user before
> suppressing.

So after the user says yes, the agent picks a form by taste. The two options
are not equivalent, and the choice is worth stating.

## Why it matters

A suppression in a central config file (`eslint.config.*`, `pyproject.toml`'s
`per-file-ignores`, `.golangci.yml`) is invisible from the code it exempts.
Someone editing the exempted line sees code that looks like it violates a rule
nobody enforces, with no rationale in sight — and the rationale is the entire
value of an approved suppression. The config file also accretes: entries
outlive the code that needed them, and nothing points at the stale ones.

An inline suppression at the point of use carries its reason to the reader who
needs it, and disappears when the code does.

## Proposal

Extend the principle with a placement rule, phrased stack-agnostically:

> Suppress at the point of use, with the rationale in the comment carrying the
> suppression, so whoever edits that line reads why. A central-config
> exemption is for one that spans files — a whole directory, a migration
> backlog — and names them explicitly.

Corollaries worth including:

- A file-level suppression under the module docstring is the point-of-use form
  when every occurrence in the file shares one reason (a CLI whose stdout is
  its interface, a module that must augment a library type).
- A permanent exemption documents the invariant; a temporary one names the
  issue tracking its removal.

## Precedent

`vzakharov/vovazakharov.com` adopted exactly this while landing an explicit
ESLint ruleset, and it reduced the central config to a single block — the one
exemption that genuinely spans files. The two single-file blocks moved into
their files, where the rationale is now next to the code it explains. Local
policy lives in that repo's `.claude/rules/eslint.md`; the stack-agnostic half
is what belongs here.
