## Body

The README's "Create a new project from this template" ends at:

> Then follow [`ADOPTING.md` § Template fork](ADOPTING.md#template-fork) to prune what doesn't apply and hydrate what does.

A fresh fork arrives carrying 29 skills, and none of them is the one that de-templates it. So the operator has to compose that prompt themselves — while every other stage of the loop has a lever: `/plan`, `/go`, `/finalize`, `/issue`, `/spinoff`.

## The proposal

A skill taking the project brief as its argument — `/<name> <here's what we're building>` — that runs § "Template fork" plus the shared tail: sweep the never rows, decide the groups by inspection, delete-or-hydrate G6, write the watermark, fill `CLAUDE.md`'s stub, rewrite `vet.sh`, and hand back the setup-script text.

It should **route through `/plan`** rather than acting directly, so the de-templating is reviewed as a diff. That is how the run behind this issue went, and the evidence the shape works: the plan caught the grouping defect in #49 before anything was deleted.

Two things this issue cannot settle alone:

- **The name.**
- **Whether a hydrated fork deletes the skill** — its job is done once, like `ADOPTING.md` — **or keeps it** as the re-run lane for when a stack finally lands.

## Findings from doing it by hand

These are worth more than the request itself: each is a place the procedure is **incomplete** rather than merely manual, and each converts into a step the skill has to carry.

1. **Deleting `docs/catalog.md` is load-bearing, and the procedure does not say so.** It is what flips `check-skill-catalog.sh` assertion 4 from "stubs are the shipped product, merely listed" to "a stub is a stowaway and fails the check", and what un-refuses `/spinoff` (whose guard is literally "if the caller has `docs/catalog.md`, stop"). Order matters: sweep the catalog first and the stub prune becomes enforced by the vet run instead of remembered.

2. **`docs/img/environment-setup-script-location.png` has no catalog row of its own.** It is `ADOPTING.md`'s only asset, so a literal never-row sweep strands it and `docs/img/` survives as an empty directory.

3. **`lastSyncedSha` is not recoverable from git in a template fork.** The fork's single commit has no ancestry in the source, so the SHA has to be derived by matching the source's commit list against the fork's `created_at`. `ADOPTING.md`'s recipe (`git -C <scratchpad>/boilerplate rev-parse HEAD`) assumes a clone that a template forker never made.

4. **`lineage` is absent from `ADOPTING.md`'s example watermark**, and `/sync-agent-infra` says that gap is not recoverable from anything else in the file — so a hand-filled watermark permanently loses the birth point unless the procedure names the field.

5. **The vet rule needs a third state.** "The boilerplate exits 0, yours exits 1" leaves a repo with *no stack yet* — the normal state of a fork taken to start a project — with no honest option: exit 1 fails step 1 of `/finalize` on every prose-only PR, which trains the loop to route around the vet run, and exit 0 is a false green the day a stack lands. The missing state is "exit 0, and trip the moment a stack manifest appears with nothing wired to it". Worth noting the tripwire has to name **two** wiring sites, not one — `scripts/vet.sh` and the session-start hook's dependency install — since nothing at all catches the second.

6. **Reverse closure is worth stating per group, because it is unevenly distributed.** Dropping G6 costs exactly one `@`-reference edit (`/bootstrap-workflow-dispatch` cites `@.claude/skills/test-on-gh/SKILL.md`) plus seven files' worth of self-guarding bare-name prose that should be **left alone** — "`/test-on-gh`, if the project has hydrated it" reads correctly when the answer is "it hasn't", and editing it makes every future `/sync-agent-infra` diff noisier for no behavioral gain. Dropping G5 costs two live `@`-references in `/finalize` plus two dead names in `/override-gh`, which unlike the G6 mentions *assert* that the files exist. Naming which is which saves the next adopter seven unnecessary edits and stops them missing four necessary ones.

7. **The G5/G2 grouping defect in #49** — the one finding that is a bug in the inventory rather than a gap in the procedure, and worth fixing whether or not this skill is ever built.
