## The gap

`scripts/vet.sh` calls `check-squash-message.sh` and nothing else. `scripts/check-skill-catalog.sh` — the check that catches a broken `@.claude/skills/<name>/SKILL.md` pointer, a skill missing its `docs/catalog.md` row, a catalog row naming a path that doesn't exist, and a stub marker that disagrees with hydration state — is left to the agent to remember, on the strength of one line in `CLAUDE.md` § "Adding or renaming a skill".

That is the wrong enforcement weight for what it catches. A dangling `@`-reference **fails silently**: the agent follows the surviving prose and skips the step it couldn't load, so nothing surfaces at the point of breakage, and the loop quietly loses a step for every session afterwards. `CLAUDE.md` already says as much where it introduces the script. A convention that has to be remembered protects against forgetting exactly as well as remembering does.

Concretely, on [#42](https://github.com/vzakharov/agent-project-boilerplate/pull/42): the branch added a hook, a new skill file (`.claude/skills/plan/exit-dialog.md`), new `@`-references and a catalog row — the whole surface this script exists to check — and `vet.sh` verified none of it. The branch's own QA checklist listed `catalog-clean` as its one automatable item, and `/finalize` still had to run it by hand beside the vet run to attest to it.

## What to do

Add the call to `scripts/vet.sh`, beside the existing `check-squash-message.sh` line.

Both lines are then **non-stack-specific**, which the ADOPTERS comment at the top of `vet.sh` currently frames around a single such line ("decide that line on its own"). That comment needs rewording to cover a pair — an adopter replacing everything around them should be told, once, that neither is theirs to drop and why.

## Why it's portable

The catalog check is adopter-safe as written: it discovers the stub set rather than hard-coding this repo's eight, and adopters take `.claude/skills/` and `docs/catalog.md` along with the loop. It reads the tree and exits — no network, no stack, fast enough to sit in a pre-push run.

## Acceptance

- `scripts/vet.sh` runs `check-skill-catalog.sh`, and a deliberately broken `@`-reference makes `./scripts/vet.sh` exit non-zero.
- The ADOPTERS comment addresses both non-stack-specific checks rather than one.
- `CLAUDE.md` § "Adding or renaming a skill" is repointed: the script is now part of the vet run, so the instruction to run it by hand is either dropped or restated as "vetting covers this" — one home for the convention, not two that can drift.
