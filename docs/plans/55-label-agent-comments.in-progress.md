# #55 — label agent-authored comments in the export

Closes #55. Export of the issue: `docs/issue/55/issue.md`.

Two pieces of work, independent but shipping together (see § "Why both here"):

- **A.** The exporter labels each comment `(agent)` / `(human)` from the Claude Code attribution footer, strips the matched footer, and `/handle` § "Step 2" stops describing the string test.
- **B.** A bare `<issue title> #<N>` session prompt routes to `/issue`, the same as a literal `/issue` invocation. (Operator rider, this session.)

## Correction to the issue's stated approach

The issue proposes hanging the label off `scripts/gh_export/markdown.py:12`'s `login_of()`, as "the one place all three renderers get an author from". **That won't work, and the reason matters for the design:** `login_of()` receives the *nested user object* (`c.get("user")`, `ev.get("actor")`, `review.get("user")`) — not the comment. The footer lives in the **body**, which `login_of` has no access to. Hosting the label there would mean changing its signature and every call site, which is strictly more churn than the alternative.

The real seam is a **body-level** helper, called at the sites that actually hold a body. That is also why the timeline needs no change: timeline events carry no bodies (`commented` is in `timeline.py`'s `_TIMELINE_SKIP`, and `reviewed` events render a state and a link), so there are two body-bearing renderers, not three.

## Decisions

**`(agent)` / `(human)`, not `(agent)` / `(operator)`.** The issue's acceptance criterion says "operator-labelled", but the issue also requires that "a third-party reviewer must still read as themselves" — and `(operator)` on a third party's comment is a false claim, in the one field a reader is being told to trust. `(human)` is true of the operator and of any reviewer, keeps the label symmetric and unmissable (the issue's actual requirement: "something a reader cannot misparse"), and serves `/handle`'s tail test unchanged — a third party's guidance is guidance to act on too. The raw login stays in place either way; the label annotates it.

**The item body gets the same treatment.** `/handle`'s review lane reads `docs/pr/<n>/pr.md`, whose PR description is normally agent-authored and carries the harness's own footer variant. Stripping it there too costs one call site and keeps the file free of a repeated block; `header_section`'s `- **Author:**` line takes the label.

## Steps

### A1 — `scripts/gh_export/authorship.py` (new)

One module, one exported pair:

- `split_agent_footer(body: str) -> tuple[bool, str]` — returns whether a trailing attribution footer was found, and the body with it removed (trailing whitespace normalized).
- `attribution(holder, body) -> str` — the `@login (agent)` / `@login (human)` string the renderers interpolate, built on `login_of`.

Detection is a single `re` pattern, **anchored at end of string** (`\s*\Z`) so a footer-shaped string mid-body never matches — an explicit acceptance criterion. It must tolerate:

- both link targets: `claude.ai/code` and `claude.com/claude-code`;
- both verbs: `_Generated by [Claude Code](…)_` (comment form, per this repo's harness rules) and `🤖 Generated with [Claude Code](…)` (the PR-description form);
- the optional preceding `---` rule, and the optional trailing `https://claude.ai/code/session_…` line the PR-description form appends;
- trailing whitespace anywhere in the block.

A short module docstring states the one durable contract: **the footer is the machine-read signal, which is why it stays mandatory on every agent-authored post** — the issue's closing note, given a home here rather than restated in a skill.

### A2 — Call sites

- `markdown.py` — `comments_section`: label the header, render the stripped body. `header_section`: label the `- **Author:**` line, and return the stripped item body (the body currently flows through `export-github-item.py`, so this is either a return-value change or a strip at that one call site — take whichever keeps `header_section`'s signature honest).
- `reviews.py` — `review_section`: both the `### Review by @…` header and each inline comment's `**@…**` line.
- `timeline.py` — unchanged, per the correction above.

### A3 — Tests, and a vet hook that runs them

The repo has **no Python test hook today** — `scripts/vet.sh` runs two shell checks and nothing else — so acceptance criteria 1–3 have nothing to assert them. This adds **no dependency**: `unittest` is stdlib, so the exporter's stdlib-only constraint holds for its tests as well.

Add `scripts/test_authorship.py`, covering exactly the stated criteria: footer present → agent; same body without it → human; footer-shaped text mid-body → human, body untouched; both link variants; both verb forms; the session-URL tail.

**Placement is load-bearing, and `unittest discover` must not be used.** Verified on this environment's Python 3.11: discovery over a directory with no `__init__.py` reports `Ran 0 tests … OK` and exits 0 — 3.11 dropped namespace-package discovery, and this repo has no `__init__.py` by design (`export-github-item.py`'s docstring states the PEP 420 arrangement). A `vet.sh` line built on `discover` would therefore certify a run that executed nothing, which is the exact false green the ADOPTERS note at the top of `vet.sh` exists to warn about.

So the test file sits **directly in `scripts/`**, beside `export-github-item.py`, and `vet.sh` runs it by path:

```bash
"$(dirname "$0")/test_authorship.py"
```

Run that way, `sys.path[0]` is `scripts/`, so `from gh_export.authorship import …` resolves exactly as it does for the exporter — confirmed working from an unrelated cwd. Add the line to the two existing ones rather than replacing the ADOPTERS framing: the boilerplate now has one checkable thing, so the "no stack-specific checks" message narrows to say so, and the `exit 0` rationale is unchanged.

**Whatever runs the tests must fail loudly when it runs none.** That is the property the `discover` route silently lacked; a direct invocation of a file with a `unittest.main()` entrypoint has it by construction.

## Why both here

B is three lines of prose in two files and shares A's subject — how a session reads what it was handed. Splitting it into its own branch/PR costs a full loop for a diff no reviewer would want separately. It is called out as its own section so the reviewer can reject it independently; if they do, A stands unchanged.

## DRY notes

- **Genuinely shared, so extracted:** footer detection is needed by three-to-four call sites across three modules. It goes in one new module (`authorship.py`) rather than in `markdown.py`, because `reviews.py` already imports from `markdown.py` and adding a body-level concern there would make `markdown` the grab-bag both other modules reach into. `login_of` stays where it is and `authorship` builds on it — the existing import direction is preserved, not inverted.
- **Deliberately not extracted:** the label strings (`(agent)`, `(human)`) live as literals inside `attribution()` only. No constant, no enum — they have exactly one producer, and CLAUDE.md's "derive from the source of truth" rule bites on shapes that *track another declaration*, which these don't.
- **Not extracted:** the four call sites each interpolate the label into a differently-shaped header (`### Comment by …`, `- **Author:** …`, `### Review by … — STATE`, `**@…** — date`). A shared header-builder would have to take the surrounding format as a parameter, which is the format string back again. `attribution()` returning the `@login (label)` fragment is the right altitude — the smallest piece all four genuinely share.
- **Reused rather than added:** `rewrite_attachment_refs` already wraps every body at these same call sites; footer-stripping composes with it at the same point instead of introducing a second pass elsewhere.
- **Not duplicated:** the "footer stays mandatory" rule gets exactly one home (`authorship.py`'s docstring). `/handle` cites the label; it does not re-explain it.
