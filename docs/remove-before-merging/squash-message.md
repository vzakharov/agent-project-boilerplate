An agent replying to a review thread posted `@<scratchpad path>` as the
body, so the thread received the path and the reply stayed on a disk
nobody else can read. `gh api -f body=@<file>` is the cause: `-f` sets
a literal string field, and only `-F` resolves a leading `@` to file
contents. Reaching for the `@` at all comes from Claude Code expanding
it in a prompt, which GitHub has no equivalent of.

Every skill in the loop requires a reply on GitHub for each comment
addressed, and none said how to post one, so the mechanics were
improvised at each call site. CLAUDE.md's GitHub comments section now
names the working forms for a PR-level comment and for a review-thread
reply, beside the bare-SHA rule — both being cases of what you type
not being what renders.

It also says to read the comment back, because the post succeeds
either way. Until someone does, a path into the agent's scratchpad
sits on a thread that may be public, and a body carrying no
attribution footer exports as a human's — so a broken reply returns to
the next session as operator guidance nobody answered.
