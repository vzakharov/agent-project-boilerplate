The exporter handled issues only, while the donor repo had replaced it
with a TypeScript version handling both. Adopting that file would make a
Node toolchain a prerequisite for every adopter, so the capability is
ported into the existing stdlib-only Python script, renamed
`export-github-item.py`. Issues still land in `docs/issue/<n>/issue.md`
unchanged; PRs land in `docs/pr/<n>/pr.md`, with the type discovered from
the API so a bare number works for either.

A PR export goes past donor parity. The donor renders a review as a
single timeline line and drops the review's text, its inline comments and
the diff hunks they hang off — the substance the issue names as the point
of PR support. This export carries all three in a `## Review threads`
section, comments grouped into reply chains, alongside a Base/Head, Draft
and Merged header block and the PR-only timeline events.

Two pre-existing bugs surfaced on the way. Attachment collection ignored
`user-attachments/files/`, so uploaded documents were never downloaded.
And pagination followed the Link header's URL, which GitHub phrases as
`repositories/{id}/…` — a form the agent proxy in Claude Code web
sessions rejects with 403, so any thread past its first page failed.
Both affected issue exports too.

Sharing `docs/pr/<n>/` with the transient body file `pr-body.py` parks
there put an export within reach of that script's `rmtree`, and of the
matching `rm -rf` in `/qa-checklist`. Both now remove `body.md` alone.
