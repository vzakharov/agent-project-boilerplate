```
`scripts/vet.sh` is the one entrypoint no adopter can decline —
`/finalize`, `/sync-branch` and `/watch-ci` all call it — so whatever it
depends on sits on the floor for every project adopting this boilerplate.
The donor repo's parallel check runner is worth taking for its reporting
alone, but taking it verbatim would have made `python3` a hard
requirement of the core PR loop for Rust, Go and Node repos with no other
reason to have it.

`scripts/run-parallel.sh` is that runner re-expressed in POSIX `/bin/sh`:
checks run concurrently with output buffered per check and printed only
for the ones that failed, a liveness line names what is still running
every 10s, and a `git status --porcelain` comparison flags files an
autofix step rewrote while still exiting 0. It takes `<label>=<command>`
pairs where the original hardcodes pnpm script names, since a
stack-agnostic boilerplate cannot assume a package manager. Buffering to
a file per child rather than in memory is what let the port drop threads
for fork-and-poll — a status file written-then-renamed makes its
existence mean "finished", so nothing needs a background ticker that
could outlive the script.

`vet.sh` stays a stub that exits 1: only the adopter knows their
commands, so the fan-out form is added beside its serial examples rather
than in place of them, in the stub itself, `CLAUDE.md`, `ADOPTING.md` and
the catalog. A two-check vet run has nothing to gain from fan-out, and
the stub should not be prescriptive about a call only the adopter can
make.

`upstream.json`'s `adopted` list now accepts a `{path: note}` entry
alongside bare paths, and records the Python original as one. A path
taken but not verbatim is not declined: filing it under `declined` would
route future upstream commits to `skip (not adopted)`, which re-tests the
recorded reason as though the decision were still open, where a noted
adoption keeps the path filtering the log so those commits surface for
`translate` — with the note stating what the local re-expression already
does differently.
```
