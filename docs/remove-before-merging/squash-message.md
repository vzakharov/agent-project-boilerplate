```
An image the operator attaches exists only as base64 inside the
session transcript, so only the session it arrived in can see it and
nothing in the repo can point at it. Keeping one meant a manual round
trip: a PR comment for the export script to pull back down, or a
commit made from a local machine.

A hook-driven extractor now writes those attachments out of the
transcript into gitignored tmp/session-images/, one file per image
plus a manifest row carrying the prompt text it arrived with, which is
what makes the image legible to a session that was not there.
Filenames derive from the record's own timestamp and uuid, and dedupe
reads the hashes already in the manifest, so a re-run writes nothing
and no second state file can drift.

Measurement rather than assumption puts the work on UserPromptSubmit:
the prompt being submitted is not in the transcript yet, so an image
lands at the start of the turn after the one it arrived in. Nothing is
committed and the directory is ignored, so the working tree stays
clean and an image reaches the repo only by being moved there. A hook
that committed on its own would commit to whatever branch HEAD sat on;
one writing into the tree /finalize sweeps would restore that tree
right after the sweep, its dedupe state being the manifest inside it.

The filter keys on a record's human origin and on top-level image
blocks, which separates an operator's attachment from the agent's own
read of an image file and from subagent turns. extension_for_bytes
moves from the GitHub exporter to scripts/lib/media.py, leaving the
hook independent of the issue loop.
```
