```
The bundled GitHub exporter only understood issues, so the one kind of
thread an agent most needs verbatim — a code review, whose substance
lives in inline comments and the diff hunks they hang off — had no
export path at all. `gh pr view` flattens a review to a one-line
timeline entry, and the review threads behind it take several
paginated calls to reassemble.

`scripts/export-github-issue.py` becomes `scripts/export-github-item.py`
and discovers the item's type from the API, so a bare number, an
`/issues/N` URL and a `/pull/N` URL all work. Issues still render to
`docs/issue/<n>/issue.md` unchanged; pull requests render to
`docs/pr/<n>/pr.md` with a Base/Head, Draft and Merged header block and
a `## Review threads` section that groups inline comments into reply
chains by `in_reply_to_id` and fences each chain's diff hunk. Review
prose goes through the same attachment download-and-rewrite pass as an
issue body. Still stdlib-only Python 3.9+, so adopting the script pulls
in no toolchain.

Two latent defects surfaced and are fixed for issues as well as PRs.
The attachment pattern matched only `user-attachments/assets/`, so
uploaded documents were left as dead links while inline images
downloaded. And pagination followed the Link header's `next` URL, which
GitHub phrases as `repositories/{id}/…` — a form the agent proxy in
Claude Code web sessions rejects with 403, so every thread past its
first page failed. Pages are now addressed with an explicit `page=`
against the `repos/{owner}/{repo}/…` path.

`docs/pr/<n>/` now holds two things: the durable export and the
transient body `scripts/pr-body.py` parks there between pull and push.
Both cleanups that used to delete the whole directory are narrowed to
the one file they own, so a QA-checklist run no longer silently
destroys an export.

Closes #9
```
