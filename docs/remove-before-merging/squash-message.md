```
An agent replying to a review thread posted `@<scratchpad path>` as the
body, so the thread received the path and the reply stayed on a disk
nobody else can read. `gh api -f body=@<file>` is the cause: `-f` sets
a literal string field, and only `-F` resolves a leading `@` to file
contents. Reaching for the `@` at all comes from Claude Code expanding
it in a prompt, which GitHub has no equivalent of.

Every skill in the loop requires a reply on GitHub for each comment
addressed, and none said how to post one, so the mechanics were
improvised at each call site. The rule now sits beside the bare-SHA
rule in CLAUDE.md's GitHub comments section — both being cases of what
you type not being what renders — and names the working forms for a
PR-level comment and for a review-thread reply.

Catching it takes reading the comment back, because the post itself
succeeds. A body carrying no attribution footer exports as a human's,
so a broken reply returns to the next session as operator guidance
nobody answered, and until someone notices, a path into the agent's
scratchpad sits on a thread that may be public. The draft survives on
disk either way, which makes the repair a PATCH of that comment rather
than a delete and re-post.
```
