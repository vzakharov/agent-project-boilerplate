```
`scripts/vet.sh` is the one entrypoint no adopter can decline —
`/finalize`, `/sync-branch` and `/watch-ci` all call it — so taking the
donor repo's parallel check runner verbatim would have put `python3` on
the floor for every Rust, Go and Node project adopting this boilerplate.
`scripts/run-parallel.sh` is that runner re-expressed in POSIX `/bin/sh`:
checks run concurrently, output is buffered per check and printed only
for the ones that failed, a liveness line names what is still running
every 10s, and a `git status --porcelain` comparison flags files an
autofix step rewrote while still exiting 0. It takes `<label>=<command>`
pairs rather than the original's hardcoded pnpm script names, since a
stack-agnostic boilerplate cannot assume a package manager. `vet.sh`
stays a stub that exits 1, with the fan-out form added beside its serial
examples in the stub, `CLAUDE.md`, `ADOPTING.md` and the catalog.

`upstream.json`'s `adopted` list now accepts a `{path: note}` entry
alongside bare paths, and records the Python original as one. A path
taken but not verbatim is not declined: `declined` would route future
upstream commits to `skip (not adopted)`, re-testing the decision as
though it were still open, where a noted adoption keeps the path
filtering the log so those commits surface for `translate`.
```
