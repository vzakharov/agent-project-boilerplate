```
An image the operator attaches exists only as base64 in the session
transcript on the VM, so it dies with the session and the next one
cannot see what was pointed at. Getting it onto the branch meant a
manual round trip: a PR comment for the export script to pull down,
or a commit from a local machine.

A hook-driven extractor now pulls those attachments out of the
transcript into docs/remove-before-merging/session-images/, one file
per image plus a manifest row carrying the prompt text it arrived
with, which is what makes the image legible to a session that was not
there. Filenames derive from the record's own timestamp and uuid, and
dedupe reads the hashes already in the manifest, so a re-run writes
nothing new and no second state file can drift.

Measurement rather than assumption puts the work on UserPromptSubmit:
the prompt being submitted is not in the transcript yet, so an image
lands at the start of the turn after the one it arrived in. Nothing is
committed. The file is left untracked for the agent to keep by
committing it with its own work, which is the decision the convention
already asks for, and a hook that committed on its own would write to
whatever branch HEAD sat on and would restore the swept tree — its
dedupe state is the manifest, and the manifest goes with the sweep.

The filter keys on a record's human origin and on top-level image
blocks, which separates an operator's attachment from the agent's own
read of an image file and from subagent turns. Extracted images land
under the tree /finalize sweeps, so one worth keeping is promoted to a
permanent home deliberately and the rest never reach the trunk.
extension_for_bytes moves from the GitHub exporter to
scripts/lib/media.py, leaving the hook independent of the issue loop.
```
