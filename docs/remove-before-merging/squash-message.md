fix: #53 count characters, not bytes, in the squash width caps (pr #58)
```

```
`scripts/check-squash-message.sh` measured line width with `${#line}`,
which counts bytes under `dash` — `/bin/sh` on Debian and Ubuntu, and
the script is `#!/bin/sh` on purpose — and under `bash` outside a UTF-8
locale. The caps are terminal columns, so what they should count is
characters. The two agree only while the message is ASCII, which is why
this stayed invisible.

Outside Latin-1 the effective cap was therefore roughly halved: two
bytes per character on Cyrillic, Greek, Hebrew and Arabic, three on CJK.
Since `scripts/vet.sh` calls this check and `/finalize` gates on the vet
run, an adopting project whose commit messages are non-Latin could not
land anything — a body wrapped correctly at 72 columns was rejected, and
the failure output compounded it by reporting the byte count under the
label `chars`.

`char_len` now deletes UTF-8 continuation bytes with `tr`, leaving one
byte per character, and the five measuring sites use it. `tr` keeps the
script's dependency floor where its own header states it, which `wc -m`
would not. `ADOPTING.md` loses the paragraph warning adopters off a
non-Latin language, the gap it pointed at being this one.

Fixes #53
